Previewing a website locally with VS Code Live Preview

How to install Microsoft's Live Preview extension, run your HTML through a local web server, see changes while you work, and understand what a localhost development URL means.

Course recommendation: for ordinary HTML, CSS, and browser-side JavaScript projects, use the Live Preview extension published by Microsoft. It hosts the files from your VS Code workspace on a small local HTTP server and can refresh the preview as you edit.

Do not confuse extensions with similar names. The extension used in this course is Live Preview, publisher Microsoft, extension ID ms-vscode.live-server. The older third-party Live Server extension is a different product.

1. Why use a local server?

A very simple HTML file can be opened directly from disk by double-clicking it. The browser then displays a URL beginning with file:///. That is useful for a quick check, but it is not the same situation as visiting a website over HTTP.

Live Preview starts a web server on your own computer and serves your project through an address such as http://127.0.0.1:3000/. Your browser becomes a client: it requests files from the local server in much the same way that it later requests files from GitHub Pages or another public web server.

Closer to real web hosting

You work with an http:// origin rather than directly opening a disk file. This makes the development setup more similar to a published site.

Automatic refresh

By default, Live Preview refreshes the preview when the document changes, so the edit → inspect → revise cycle is faster.

Better project paths

The server has a defined workspace root. Relative links between HTML, CSS, JavaScript, images, and data files behave like links in a web project.

Useful for JavaScript work

Later in the course, browser APIs such as fetch() are much easier to test from an HTTP origin than from a file:/// page.

Important: this is a local server. It is intended for development on your computer. Starting Live Preview does not publish your site to the Internet and does not replace GitHub Pages.

2. Live Preview and the built-in VS Code HTML preview

Modern versions of VS Code can also preview an HTML file directly in the Integrated Browser without installing an extension. Microsoft added this built-in HTML preview in VS Code 1.121 (May 2026). You may therefore see both Open in Integrated Browser and Live Preview commands in VS Code.

Option When it is useful Course use
Built-in HTML preview Quickly render a local HTML file inside VS Code with no extension installation. Fine for a quick visual check.
Microsoft Live Preview extension Run the project through an explicit local HTTP server, use live refresh, external browser preview, server logging, and related development features. Recommended when we want a normal local web-development server workflow.

Live Preview can itself use VS Code's Integrated Browser as the preview window. In other words, the server and the browser window used to view it are separate ideas.

3. Install Microsoft Live Preview

  1. Open Visual Studio Code. Start the normal desktop version of VS Code.
  2. Open the Extensions view. Select the Extensions icon in the Activity Bar on the left, or press Ctrl + Shift + X on Windows/Linux.
  3. Search for Live Preview. Several similarly named extensions may appear, so inspect the publisher carefully.
  4. Select the extension published by Microsoft. Confirm that its extension ID is ms-vscode.live-server.
  5. Select Install. VS Code downloads the extension from the Visual Studio Marketplace and enables it.
Verification: after installation, open the Command Palette with Ctrl + Shift + P and type Live Preview. You should see commands such as Live Preview: Show Preview and Live Preview: Start Server.

Optional command-line installation

If the code command is available in your terminal, the same extension can be installed with: 

code --install-extension ms-vscode.live-server

For beginners, installing from the Extensions view is preferable because you can see the extension name, publisher, description, and documentation before installing it.

4. Open the project correctly

Live Preview works best when VS Code has opened the project folder, not merely one loose HTML file. The folder becomes the workspace root from which the local server serves files.

  1. In VS Code, choose File → Open Folder....
  2. Select the folder that contains your website project. In a simple course exercise, this will normally be the folder containing index.html.
  3. Confirm that you can see the project files in VS Code's Explorer.
  4. Open index.html in the editor.

Why the folder matters: if an HTML file is outside the server root, relative paths may not resolve as expected. Microsoft's Live Preview documentation specifically recommends opening the workspace at the project root.

5. Start the preview

With index.html open, use any one of these methods:

Editor button

Select the Live Preview / preview button in the upper-right area of the editor while the HTML file is active.

Right-click

Right-click inside the HTML editor and choose Show Preview if the Live Preview command is shown in the context menu.

Command Palette

Press Ctrl + Shift + P, type Live Preview, and choose Live Preview: Show Preview.

By default, Live Preview first tries port 3000. If that port is already in use, the extension can try a different free port. The host defaults to 127.0.0.1, which refers to your own computer.

Depending on your VS Code version and settings, the preview may appear inside VS Code in the Integrated Browser. You can also use an external browser. Open the Command Palette and choose Live Preview: Show Preview (External Browser) when you specifically want to inspect the page in your normal browser window.

Try a minimal page

Create or replace index.html with a small test page:

<!DOCTYPE html>
<html lang="en">
<head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>Live Preview Test</title>
</head>
<body>
    <h1>Hello from my local server</h1>
    <p>This page is being served from my own computer.</p>
</body>
</html>

Start Live Preview, then change the heading text. The preview should update. The extension's default auto-refresh mode reacts to editor changes; depending on your settings, refresh can instead be configured to happen on saved changes only.

Still save your files. A live preview can show a change before you have saved it to disk. Git records changes to files, not the temporary unsaved editor state. Before committing your work, save the files with Ctrl + S.

6. Understand the local URL

A Live Preview address may look like this:

http://127.0.0.1:3000/index.html
http://
The protocol used for the request. Your browser is requesting a web resource over HTTP.
127.0.0.1
The loopback IP address. It means “this computer.” localhost is commonly used for the same idea.
:3000
The TCP port on which the local server is listening. Live Preview uses port 3000 by default if it is free.
/index.html
The path of the resource being requested from the local server.

Prediction question: if your classmate types your 127.0.0.1:3000 address into their laptop, will they see your page? Normally, no. On their computer, 127.0.0.1 refers to their own computer, not yours.

7. Relative paths and the server root

Suppose your project has this structure:

my-site/
├── index.html
├── css/
│   └── style.css
├── js/
│   └── app.js
└── img/
    └── manuscript.jpg

Then index.html can refer to the other files with relative URLs:

<link rel="stylesheet" href="css/style.css">
<img src="img/manuscript.jpg" alt="Historical manuscript page">
<script src="js/app.js"></script>

If my-site is the VS Code workspace root, Live Preview can serve these files as one coherent project. If images, styles, or scripts unexpectedly return 404 errors, first check the path spelling and then check whether you opened the correct folder in VS Code.

8. Normal DE0824 workflow

  1. Open the repository folder in VS Code. Work from the repository root so that file paths and Git status are easy to understand.
  2. Pull or synchronize before editing. Make sure your local repository has the latest remote changes.
  3. Open index.html and start Live Preview. Keep the preview visible while you work.
  4. Edit a small piece of HTML or CSS. Predict what the browser should display before looking at the result.
  5. Inspect the preview. If the result differs from your prediction, use browser Developer Tools and VS Code to diagnose the difference.
  6. Save the file. Use Ctrl + S even if Live Preview has already shown the unsaved change.
  7. Review the Git diff. Confirm that the actual file changes match what you intended.
  8. Commit and push. Record a coherent checkpoint and send the commit to GitHub.
  9. Check GitHub Pages. Local preview tells you what works on your computer; the published URL confirms that the deployed site also works.

9. Useful Live Preview commands and settings

Command / setting Purpose
Live Preview: Show Preview Open a preview for the current HTML file.
Live Preview: Start Server Start the local server explicitly.
Live Preview: Show Preview (External Browser) Open the locally served page in your normal browser.
Live Preview: Stop Server Stop the local server when you are finished.
livePreview.autoRefreshPreview Controls whether refresh happens on all editor changes, on saved changes, or never.
livePreview.portNumber Initial local server port. The default is 3000.
livePreview.serverRoot Optionally changes which folder inside the workspace is treated as the server root.
livePreview.useIntegratedBrowser Controls whether Live Preview uses VS Code's Integrated Browser for embedded previews.

You do not need to change these settings for ordinary Week 2 work. The defaults are sufficient. Learn the normal workflow first; customize only when you have a concrete reason.

10. Troubleshooting

Symptom Likely cause What to check
The Live Preview command is missing. The extension is not installed, is disabled, or you selected a different extension. Open Extensions and verify Live Preview, publisher Microsoft, ID ms-vscode.live-server.
The preview opens the wrong file. A different editor tab is active or a default preview path is configured. Open the intended index.html and run Live Preview: Show Preview again.
CSS, images, or scripts are missing. A relative path is wrong or the workspace/server root is wrong. Check spelling and folder structure. Open the whole project folder, not a loose file.
The browser reports 404 Not Found. The requested path does not exist under the server root. Compare the browser URL with the actual folders and filenames. Remember that deployment systems may be case-sensitive.
The page does not update. Auto-refresh may be disabled or configured to refresh only on save. Save the file, then inspect the Live Preview: Auto Refresh Preview setting.
The address is not using port 3000. Port 3000 was already occupied. This is normally harmless. Use the port Live Preview selected.
The local page works, but GitHub Pages does not. The problem is in Git/push/deployment, or a path behaves differently after publication. Check that changes were saved, committed, pushed, and that the GitHub Pages URL and browser Developer Tools show the expected files.

Use Developer Tools, not guessing

When a preview is wrong, inspect evidence. In an external browser, open Developer Tools with F12 or Ctrl + Shift + I. Useful places include:

  • Elements / Inspector: inspect the DOM and applied CSS.
  • Console: read JavaScript errors and diagnostic messages.
  • Network: check whether CSS, JavaScript, images, or data files were successfully requested.

11. Small practice exercise

Use this exercise to confirm that your setup works before doing larger course work.

  1. Create a folder named live-preview-test.
  2. Open that folder in VS Code.
  3. Create index.html containing a heading and paragraph.
  4. Start Live Preview and identify the protocol, host, port, and path in the URL.
  5. Change the heading. Confirm that the preview updates.
  6. Create style.css, link it from the HTML, and change one visible style.
  7. Deliberately misspell the CSS filename in the HTML. Observe the failure.
  8. Use Developer Tools → Network or the browser console to help identify the problem.
  9. Fix the filename and verify that the style returns.
  10. Save all files and inspect the changes in VS Code Source Control.

You are ready for course work when you can explain this chain:
edit HTML/CSS in VS Code → Live Preview serves the files locally → browser requests the files over HTTP → you inspect the result → save → commit with Git → push to GitHub → GitHub Pages serves the published version.
