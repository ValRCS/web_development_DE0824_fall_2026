HTML basics: giving a web page structure and meaning

A guided introduction to the small set of HTML elements we need to build our first structured pages: document structure, headings, paragraphs, lists, links, and images.

Course home Week 2 workflow and technologies Practice tasks References

Goal for the second academic hour: move from editing a single piece of text to creating a small but properly structured HTML document. We will build these ideas incrementally during live coding. This page is the reference you can inspect before, during, and after the session.

Important: this teaching page itself already uses some HTML elements and CSS that we have not studied yet, simply to make a long reference page easier to read. For Week 2, concentrate on the code examples in the grey boxes and on what they do in the browser.

1. What HTML is for

HTML stands for HyperText Markup Language. It is the language browsers use to describe the content and structure of a web document.

The central idea for this week is simple: HTML should describe what a piece of content is, not merely how we want it to look. Presentation will come later with CSS.

Digital Humanities document idea HTML structure
Title of a digital edition or collection <h1>
Section heading <h2>, <h3>, ...
Paragraph of explanatory text <p>
List of objects, sources, authors, or categories <ul> or <ol>
Reference to another web resource <a>
Scan, photograph, map, manuscript image, or logo <img>

Key idea: a heading is a heading because of its role in the document, not because the browser happens to display it in large bold text.

2. Start with a complete HTML document

An HTML file is an ordinary text file, usually with the .html extension. A useful starting document looks like this:

Example 1 · Minimal complete page

<!DOCTYPE html>
<html lang="en">
<head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>Latvian Historical Newspapers</title>
</head>
<body>
    <h1>Latvian Historical Newspapers</h1>
    <p>A small Digital Humanities collection.</p>
</body>
</html>
Part Purpose
<!DOCTYPE html> Tells the browser to interpret the document using modern HTML rules.
<html lang="en"> The root element. The lang attribute identifies the document language.
<head> Information about the document rather than the main visible page content.
<meta charset="UTF-8"> Declares UTF-8 text encoding, which we want for Latvian and other Unicode text.
<title> The document title shown in the browser tab and used in other browser contexts.
<body> The main content rendered in the browser window.
Prediction: change only the text inside <title>. Where does the change appear? Then change the text inside <h1>. Is the result in the same place?

3. Elements, tags, content, and attributes

We need four pieces of vocabulary. Consider this paragraph:

Example 2 · A simple element

<p>A historical newspaper.</p>
  • <p> is the opening tag.
  • A historical newspaper. is the content.
  • </p> is the closing tag.
  • The opening tag, content, and closing tag together form the element.

Elements can also have attributes. Attributes add information to the element. A link needs to know where it should lead:

Example 3 · An element with an attribute

<a href="https://www.lnb.lv/">National Library of Latvia</a>

Here href is the attribute name and https://www.lnb.lv/ is its value.

4. Elements can be nested

HTML elements frequently contain other elements. For example, a paragraph can contain a link:

Example 4 · Nesting

<p>
    Explore the
    <a href="https://www.lnb.lv/">National Library of Latvia</a>.
</p>

A useful rule is to think of nested HTML like properly nested parentheses. Close the inner element before closing the outer one.

Correct

<p>
    Read <strong>this document</strong>
    carefully.
</p>

Incorrect nesting

<p>
    Read <strong>this document
</p></strong>
Browsers are deliberately tolerant of many HTML mistakes and may still display something. "The browser displayed it" does not necessarily mean the markup is well structured.

5. Headings and paragraphs

Headings describe the hierarchy of a document. HTML provides heading levels <h1> through <h6>. Paragraphs use <p>.

Example 5 · A small document hierarchy

<h1>Latvian Historical Newspapers</h1>

<p>
    This page introduces several digitised Latvian newspapers.
</p>

<h2>Jaunākās Ziņas</h2>

<p>
    Jaunākās Ziņas was an important Latvian daily newspaper.
</p>

<h2>Digitised collections</h2>

<p>
    Historical newspapers can be studied both as documents
    and as machine-readable textual corpora.
</p>

Choose heading levels according to structure. Do not choose an <h4> merely because you prefer its default size. CSS will later control appearance.

Prediction: if you change an <h2> to an <h5>, will the browser allow it? Has the document hierarchy improved or worsened?

6. Lists

Lists are common in research pages: collections, people, sources, metadata fields, workflow steps, bibliographies, and many other kinds of grouped information.

Unordered list

Use when the order is not important.

<ul>
    <li>Newspapers</li>
    <li>Books</li>
    <li>Photographs</li>
</ul>

Ordered list

Use when the sequence itself matters.

<ol>
    <li>Find the source</li>
    <li>Inspect the metadata</li>
    <li>Read or download the document</li>
    <li>Analyse the text</li>
</ol>

In both cases, individual items are represented by <li>.

Try it: change only <ul> and </ul> to <ol> and </ol>. What visible change occurs? Has the meaning changed as well?

7. Links: the "hypertext" in HTML

A web page becomes part of the Web by linking to other resources. The anchor element <a> uses the href attribute to identify its destination.

Example 6 · Absolute URL

<a href="https://developer.mozilla.org/en-US/docs/Web/HTML">
    Learn more about HTML on MDN
</a>

An absolute URL contains the full address, including the scheme and host. It is typically used when linking to another website.

Example 7 · Relative URL

<a href="technologies.html">Week 2 workflow</a>

A relative URL is interpreted relative to the current document's location. Because this page and technologies.html are in the same folder, only the filename is needed.

To reach the course index.html from this page, we move up two folders:

Example 8 · Moving up folders

<a href="../../index.html">Course home</a>
web_development_DE0824_fall_2026/
├── index.html
└── lectures/
    └── week02/
        ├── technologies.html
        └── html_intro.html

Debugging rule: when a relative link does not work, first ask: "Where is the current HTML file, and where is the target file relative to it?"

8. Images

The <img> element embeds an image. Two attributes matter immediately: src gives the image location, and alt provides a text alternative.

Example 9 · Image from this repository

<img
    src="../../img/rtu_logo_en-1978560996.png"
    alt="Riga Technical University logo"
>

Unlike a paragraph or heading, <img> is a void element: it does not wrap content and therefore has no closing </img> tag.

The alt text should communicate the image's meaning or function when the image cannot be seen. It is important for accessibility and also helps when an image fails to load.

Deliberately break it: change one character in the src filename, refresh the browser, and observe what happens. Then use the path and VS Code's file explorer to diagnose and repair the problem.

9. A small amount of inline meaning

If time permits, two useful elements inside paragraphs are <strong> and <em>. Their purpose is semantic, even though browsers also give them a visible default style.

Example 10 · Importance and emphasis

<p>
    This collection contains
    <strong>primary historical sources</strong>.
</p>

<p>
    Historical spelling may differ
    <em>substantially</em> from modern Latvian.
</p>
  • <strong> marks strong importance.
  • <em> marks emphasis.

10. Put the pieces together

By the end of this session, every part of the following small page should be understandable.

Example 11 · Complete miniature Digital Humanities page

<!DOCTYPE html>
<html lang="en">
<head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>Historical Newspaper Collection</title>
</head>
<body>
    <h1>Historical Newspaper Collection</h1>

    <p>
        A small collection of resources for studying
        historical Latvian newspapers.
    </p>

    <h2>Collections</h2>

    <ul>
        <li>Newspapers</li>
        <li>Books</li>
        <li>Photographs</li>
    </ul>

    <h2>Research workflow</h2>

    <ol>
        <li>Find a source</li>
        <li>Inspect its metadata</li>
        <li>Read or download the document</li>
        <li>Analyse the text</li>
    </ol>

    <h2>Resources</h2>

    <p>
        Visit the
        <a href="https://www.lnb.lv/">National Library of Latvia</a>.
    </p>

    <img
        src="img/rtu_logo_en-1978560996.png"
        alt="Riga Technical University logo"
    >
</body>
</html>
Notice the image path in the miniature example: it assumes that the HTML file is in the repository root next to the img folder. Relative paths always depend on where the current HTML file is located.

11. Practice: modify a page rather than starting from nothing

During live coding we will build a similar page incrementally. Afterwards, make your own small variation. The goal is to understand each change, not to type a large amount of markup.

  1. Add one new section using an <h2> and a <p>.
  2. Add a list containing at least three items relevant to a DH topic.
  3. Add one external link to a library, archive, museum, corpus, research project, or other DH resource.
  4. Add one image that you control or that is already part of your repository, with appropriate alt text.
  5. Save the file, refresh it in the browser, and verify each change.

Optional challenge: create a second HTML page and link the two pages together using relative URLs.

12. Common mistakes to diagnose

Symptom Likely cause What to inspect
A link gives a 404 page or opens the wrong file. Incorrect relative path or filename. Current file location, target location, spelling, and capitalization.
An image is broken. Incorrect src path or missing file. Repository folders and exact filename.
Unexpectedly large or small heading. Wrong heading level chosen for appearance rather than structure. The document hierarchy: h1, then appropriate subsection levels.
Text appears but the structure seems strange. Missing or incorrectly nested closing tags. Indentation and matching opening/closing tags.
Latvian characters display incorrectly. Encoding problem. <meta charset="UTF-8"> and how the file was saved.

A productive debugging habit is to change one thing at a time, save, refresh, and observe. If the result is wrong, inspect the smallest recent change before rewriting the page.

13. What you should be able to do after Week 2

  • Recognize the basic structure of a complete HTML document.
  • Explain the difference between an element, tag, content, and attribute.
  • Distinguish the document <head> from the visible <body>.
  • Create a logical hierarchy with headings and paragraphs.
  • Create ordered and unordered lists.
  • Create links and distinguish absolute URLs from relative URLs.
  • Insert an image using src and meaningful alt text.
  • Nest simple elements correctly.
  • Use VS Code and a browser together to edit, save, refresh, inspect, and debug a page.

14. What deliberately comes later

We are keeping Week 2 small. The following topics are useful, but they are easier to understand after the basic document vocabulary is comfortable:

  • semantic page structure such as <header>, <main>, <nav>, <section>, and <footer>;
  • figures, quotations, citations, dates, and other richer document semantics;
  • tables and forms;
  • generic containers such as <div> and <span>;
  • CSS for presentation;
  • JavaScript for behavior and interaction.
