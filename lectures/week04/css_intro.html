Introduction to CSS: styling HTML

HTML gives a document structure and meaning. CSS controls its presentation: colors, fonts, text styling, backgrounds, and other visual choices. This week we learn how CSS rules find HTML elements and how the browser decides which styles apply.

Course home Week 3 HTML Optional practice CSS references

Week 4 goal: take a semantically structured HTML document and give it a deliberate visual presentation using basic CSS. By the end of the session you should be comfortable writing simple rules, using element, class, and ID selectors, styling text and colors, and diagnosing basic cascade problems with browser Developer Tools.

About this teaching page: this reference page itself uses CSS features beyond today's minimum vocabulary so that a long document remains readable. Concentrate on the examples in the code boxes and on the small CSS rules we build incrementally.

1. Start with meaningful HTML

In Weeks 2 and 3 we deliberately concentrated on HTML before styling. That separation matters. HTML should describe what the content is; CSS should describe how that content is presented.

Starting point · A small cultural-heritage record

<article class="record">
    <h1>Letter from Rainis to Aspazija</h1>

    <p class="metadata">
        Author: Rainis · 1905
    </p>

    <p>
        A digitised historical letter from a manuscript collection.
    </p>

    <h2>Description</h2>

    <p>
        The document records correspondence from the early
        twentieth century.
    </p>
</article>

Even without our own CSS, the browser does not show completely unformatted text. Headings are larger, paragraphs have spacing, links are usually underlined, and lists have markers. Browsers provide a built-in user-agent stylesheet with sensible default styles for HTML elements.

Prediction: if you have written no CSS, why is an <h1> still larger and bolder than a paragraph? Inspect it in Developer Tools and look for styles supplied by the browser.

2. Your first CSS rule

A CSS stylesheet contains rules. A rule identifies one or more HTML elements and supplies declarations that change their presentation.

Example 1 · One selector and one declaration

h1 {
    color: darkblue;
}
h1
The selector: which HTML elements should this rule target?
color
The property: which aspect of presentation are we changing?
darkblue
The value: what value should that property receive?
color: darkblue;
A declaration: a property and value separated by a colon.

Example 2 · Several declarations in one rule

h1 {
    color: darkblue;
    font-family: Georgia, serif;
    font-size: 2rem;
}

Declarations are written inside curly braces. A semicolon separates one declaration from the next. CSS whitespace and indentation are mainly for readability, so use a consistent style that makes the structure obvious.

3. Three places CSS can appear

You will encounter three common ways of attaching CSS to HTML. We need to recognize all three, but for ordinary course work we will normally prefer a separate external stylesheet.

Inline style

<p style="color: red;">
    Important note
</p>

The declaration is placed directly in one HTML element's style attribute.

Internal stylesheet

<style>
    p {
        color: red;
    }
</style>

CSS rules are placed in a <style> element, normally in the document <head>.

External stylesheet

<link
    rel="stylesheet"
    href="styles.css"
>

CSS lives in its own file and the HTML document links to it.

Course convention: use an external stylesheet for normal pages. It keeps HTML structure separate from presentation and lets several HTML pages share the same visual rules.

4. Create and link an external stylesheet

Suppose an HTML file and stylesheet are in the same folder: 

my-project/
├── index.html
└── styles.css

Link the stylesheet inside the HTML <head>:

Example 3 · Link styles.css from index.html

<head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>Historical Letter</title>

    <link rel="stylesheet" href="styles.css">
</head>

The href value is a relative URL, just like the relative links and image paths from earlier weeks. If the CSS file is in a subfolder, the path must reflect that: 

my-project/
├── index.html
└── css/
    └── styles.css
<link rel="stylesheet" href="css/styles.css">

Deliberately break it: change the stylesheet filename in href, refresh the page, and observe what happens. Then use the browser Network panel or Elements panel to help diagnose the missing stylesheet.

5. Selectors: choosing what to style

The selector is the connection between CSS and the HTML document. This week we need a small, reliable selector vocabulary: element/type selectors, class selectors, ID selectors, selector lists, and one simple descendant relationship.

MDN basic selectors MDN selector reference

Element or type selector

Writing the name of an HTML element selects all elements of that type.

Example 4 · Style every paragraph

p {
    color: #333333;
}

Example 5 · Style every level-two heading

h2 {
    color: darkblue;
}

Class selector

A class describes a reusable category. Many HTML elements may share the same class value. In CSS, a class selector begins with a period.

Example 6 · Reusable metadata styling

<p class="metadata">Author: Rainis</p>
<p class="metadata">Year: 1905</p>
.metadata {
    color: gray;
    font-style: italic;
}

Notice: the HTML contains class="metadata", but the CSS selector is .metadata. The period is CSS selector syntax; it is not part of the class name stored in HTML.

ID selector

An id identifies one particular element in the document. In CSS, an ID selector begins with #.

Example 7 · Style one identified section

<section id="featured-item">
    ...
</section>
#featured-item {
    background-color: lightyellow;
}
CSS selector What it matches HTML example
p Every paragraph element. <p>...</p>
.metadata Every element whose class list contains metadata. <p class="metadata">...</p>
#featured-item The element whose id is featured-item. <section id="featured-item">...</section>

Selector list: give several selectors the same declarations

Example 8 · Style several heading levels together

h1,
h2 {
    font-family: Georgia, serif;
    color: #243b53;
}

The comma means "apply these declarations to elements matching h1 or h2."

Descendant selector: select something inside something else

Example 9 · Style links that are inside navigation

nav a {
    text-decoration: none;
    font-weight: bold;
}

Read nav a as: "select <a> elements that are descendants of a <nav> element." We will study more advanced selector relationships later; do not try to memorize the entire selector language now.

6. Colors and backgrounds

Two properties give immediate visible feedback: color controls the foreground text color, while background-color controls an element's background.

Example 10 · Foreground and background

body {
    color: #252525;
    background-color: #f4f1e8;
}

h1 {
    color: darkblue;
}

CSS supports several ways to write color values. For Week 4 it is enough to recognize these commonly encountered forms:

Named color

color: darkblue;

Hexadecimal

color: #243b53;

RGB

color: rgb(36 59 83);

HSL

color: hsl(210 39% 23%);

You do not need to memorize every color notation. The important idea is that CSS properties accept values with defined syntax, and several different notations can represent colors.

Visual design must remain readable. Avoid combinations such as very light gray text on a white background. Text and background need sufficient contrast for comfortable reading and accessibility.

7. Typography and text styling

A few CSS properties can substantially change the character and readability of a page. Start with a font family for the whole document.

Example 11 · A font stack with fallbacks

body {
    font-family: Arial, Helvetica, sans-serif;
}

The browser tries the fonts from left to right. If Arial is unavailable, it tries Helvetica; if neither named font is available, it uses an available sans-serif font. Generic families such as serif, sans-serif, and monospace are useful fallbacks.

Example 12 · Headings and metadata

h1,
h2 {
    font-family: Georgia, "Times New Roman", serif;
}

.metadata {
    font-style: italic;
    color: #666666;
}
Property Example Typical effect
font-family font-family: Georgia, serif; Chooses a prioritized font family list.
font-size font-size: 1.2rem; Changes text size.
font-weight font-weight: bold; Changes the weight of the text.
font-style font-style: italic; Commonly switches between normal and italic styling.
line-height line-height: 1.6; Controls the distance between lines of text.
text-align text-align: center; Controls horizontal alignment of inline content.
text-decoration text-decoration: none; Controls decorations such as underlines.

rem is a relative length unit based on the root element's font size. We can use it in simple examples now, but Week 5 will treat sizing and the box model more systematically.

8. Inheritance: some values flow through the document tree

HTML elements form a tree. For some CSS properties, a child element inherits the computed value from its parent when it has no competing value of its own. Text-related properties frequently behave this way.

Example 13 · Set text styles once on body

body {
    color: #252525;
    font-family: Arial, Helvetica, sans-serif;
}

Paragraphs, headings, links, and many nested text elements can inherit the font-family from body. The color property is also inherited unless another rule gives a descendant a different color.

Typical inherited property

article {
    color: darkslategray;
}

Text inside the article normally inherits this color unless another declaration overrides it.

Typical non-inherited property

article {
    border: 2px solid black;
}

Nested paragraphs do not each receive their own border merely because the article has one.

Prediction: if body sets a font family and a paragraph contains an <em> element, which font family will the emphasized text normally use?

9. The cascade: when several rules compete

CSS means Cascading Style Sheets. More than one declaration can match the same element and property, so the browser needs rules for choosing the value that actually applies.

Example 14 · Same selector, later rule

p {
    color: blue;
}

p {
    color: green;
}

For this simple case, both selectors have the same specificity and both are author CSS, so the later declaration wins: matching paragraphs become green.

Example 15 · A class is more specific than a type selector

p {
    color: blue;
}

.metadata {
    color: gray;
}

A paragraph with class="metadata" matches both rules. For the simple author styles we use this week, the class selector is more specific than the element selector, so its gray color wins.

Example 16 · Inline style

<p class="metadata" style="color: red;">
    Author: Rainis
</p>

Inline declarations have very high precedence among normal author styles. This is one reason we avoid using inline CSS as our ordinary design method: it makes later stylesheet maintenance and debugging harder.

Week 4 working model: first ask which rules match the element. Then look at selector specificity and source order. The complete cascade also considers origins, importance, cascade layers, and other mechanisms; we do not need the full algorithm yet.

10. Use Developer Tools to inspect CSS

CSS debugging should begin immediately. Browser Developer Tools show the matched rules, which declarations are active, which have been overridden, and what final computed values the browser is using.

  1. Open the page in your browser.
  2. Right-click an element and choose Inspect.
  3. In the Elements/Inspector panel, select the element you want to understand.
  4. Look at the Styles/Rules panel to see matching CSS rules.
  5. Look for crossed-out declarations: they matched, but another declaration won.
  6. Use the Computed panel to find the final value of a property such as color or font-family.
  7. Temporarily edit or disable a declaration and observe the page change immediately.

Example 17 · A useful debugging conflict

p {
    color: green;
}

.metadata {
    color: gray;
}

Inspect a paragraph with class="metadata". The browser can show that both rules match, while the losing color: green declaration is crossed out.

When CSS "does not work", do not immediately add more selectors. First inspect the element. Common causes are an incorrect stylesheet path, a selector that does not match, a misspelled property, an invalid value, or another declaration winning the cascade.

11. Put the pieces together

We can now give the Week 3 cultural-heritage record a simple, deliberate presentation. The example is intentionally modest: it demonstrates selectors, colors, typography, inheritance, and a descendant selector without moving into layout systems.

Example 18 · styles.css

body {
    color: #252525;
    background-color: #f4f1e8;
    font-family: Arial, Helvetica, sans-serif;
    line-height: 1.6;
}

h1,

    color: #243b53;
    font-family: Georgia, "Times New Roman", serif;

.metadata {

12. Common mistakes to diagnose

Symptom Likely cause What to inspect
No styles from the external file appear. The stylesheet is not loading. The <link> element, relative path, filename, and Network panel.
A class rule does not match anything. The CSS period is missing or the class name differs. .metadata in CSS versus class="metadata" in HTML.
An ID rule does not apply. The # selector or ID value is incorrect. #featured-item versus id="featured-item".
One declaration is ignored. Invalid syntax or an unsupported/invalid value. Property spelling, colon, value, semicolon, and DevTools warning indicators.
A valid declaration is crossed out. Another matching declaration won the cascade. Matched rules, specificity, source order, and inline styles.
Text elsewhere changes unexpectedly. A broad selector or inherited property affects more elements than expected. Whether you styled body, all p elements, or a reusable class.
colour: red; has no effect. The property name is misspelled. CSS uses the property name color.

Broken declaration

h1 {
    color red;
}

The colon between property and value is missing.

Broken class selector

metadata {
    color: gray;
}

This selects an HTML element named <metadata>, not a class.

Debugging routine: save → refresh → inspect the exact element → check whether the stylesheet loaded → check whether the selector matched → check whether the declaration is valid → check whether another rule won.

13. Optional at-home practice

Start with a small, semantically structured HTML page from Week 3. Do not rebuild it from scratch. Add an external styles.css file and make controlled changes that you can explain.

  1. Link an external stylesheet correctly.
  2. Use at least one element selector.
  3. Use at least one class selector on two or more HTML elements.
  4. Use one ID selector for a genuinely unique element.
  5. Use one selector list such as h1, h2.
  6. Use one simple descendant selector such as nav a.
  7. Set a document font family with sensible fallbacks.
  8. Change at least one text color and one background color.
  9. Use at least two text-related properties such as font-weight, font-style, line-height, or text-decoration.
  10. Create one intentional conflict between two CSS rules and use Developer Tools to determine which rule wins.

Optional challenge: after finishing, remove one CSS declaration at a time and predict the visible effect before refreshing. The goal is to understand the relationship between each rule and the resulting page, not simply to make the page look more elaborate.

14. What you should be able to do after Week 4

  • Explain the different responsibilities of HTML and CSS.
  • Recognize a CSS rule, selector, declaration, property, and value.
  • Link an external stylesheet to an HTML document with the correct relative path.
  • Use element/type, class, and ID selectors.
  • Use a selector list and a simple descendant selector.
  • Change foreground and background colors.
  • Use a basic font stack and common text styling properties.
  • Explain the basic idea of inheritance.
  • Explain why multiple matching rules can compete in the cascade.
  • Use specificity and source order as a beginner-level model for resolving ordinary author-style conflicts.
  • Use browser Developer Tools to inspect matched and computed CSS.
  • Diagnose common stylesheet, selector, syntax, and cascade mistakes.

15. What deliberately comes later

CSS is a large language. Week 4 establishes the connection between HTML and styling without trying to introduce every layout and design mechanism at once.

  • Week 5: the box model, content, padding, borders, margins, sizing, and positioning/layout fundamentals.
  • Week 6: responsive design, media queries, and Flexbox.
  • Week 7: CSS Grid, pseudo-classes, and further responsive layout practice.
  • Week 8: transitions, transforms, animations, and selected external web resources.

You will see margin, padding, width, borders, and advanced layout rules in real stylesheets—including the CSS used by this reference page. Do not try to master them today. Week 5 will give those properties the box-model explanation they need.
