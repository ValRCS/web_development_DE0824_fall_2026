CSS Grid: two-dimensional layout

Week 6 used Flexbox to arrange items mainly along one axis. This week we add CSS Grid: a browser-native layout system designed for rows and columns working together.

Course home Week 6 Flexbox Responsive Grid Pseudo-classes Practice References

Week 7 goal: build and debug two-dimensional layouts with CSS Grid. By the end of the session you should be able to create grid containers, define flexible tracks, use gaps, understand automatic placement, place selected items, create responsive grids, use named grid areas, and decide when Grid or Flexbox is the clearer layout tool.

Connection to Week 6: Grid does not replace Flexbox. A useful first approximation is Flexbox for one-dimensional relationships and Grid for two-dimensional relationships. Real pages frequently use both.

1. From Flexbox to Grid

Imagine the same digital collection cards used in Week 6. Flexbox is excellent when we primarily care about arranging a sequence of cards. Grid becomes especially useful when we want the cards to follow shared rows and columns.

Starting HTML

<section class="collections">
    <article class="collection">Manuscripts</article>
    <article class="collection">Newspapers</article>
    <article class="collection">Photographs</article>
    <article class="collection">Maps</article>
    <article class="collection">Letters</article>
    <article class="collection">Books</article>
</section>

The smallest useful Grid

.collections {
    display: grid;
    grid-template-columns: 1fr 1fr 1fr;
    gap: 1rem;
}

2. Grid container, items, tracks, lines, and cells

An element with display: grid becomes a grid container. Its direct children become grid items. The grid is formed from horizontal and vertical lines.

Track

The space between two adjacent grid lines: a row track or column track.

Cell

The smallest area bounded by one pair of row lines and one pair of column lines.

Area

One or more adjacent cells. Areas can also be given names.

Gap

Space between tracks, using the same gap idea encountered with Flexbox.

Common mistake: as with Flexbox, put display: grid on the parent of the elements you want Grid to arrange.

3. Define columns with track sizes

Grid lets us define track sizes explicitly. Start with fixed dimensions to make the mechanism visible, then move quickly to flexible sizing.

Three fixed-width columns

.collections {
    display: grid;
    grid-template-columns: 200px 200px 200px;
}

Fixed widths are easy to understand but often make poor responsive layouts. CSS Grid provides the fr unit to distribute available space.

4. The fr unit: fractions of available space

Equal flexible columns

.collections {
    grid-template-columns: 1fr 1fr 1fr;
}

The middle track receives a larger share

.collections {
    grid-template-columns: 1fr 2fr 1fr;
}
1fr
2fr
1fr

You can combine fixed and flexible tracks:

.page {
    grid-template-columns: 220px 1fr;
}

This is a natural pattern for a fixed-ish filter/sidebar region beside flexible main content.

5. Avoid repetition with repeat()

Instead of writing the same track size repeatedly, use repeat().

Equivalent three-column definitions

grid-template-columns: 1fr 1fr 1fr;

/* The same idea, more clearly expressed */
grid-template-columns: repeat(3, 1fr);

Prediction: what happens if you change 3 to 2 while leaving six cards in the HTML? Test before reading the next section.

6. Rows and automatic placement

If we define three columns and have six items, the browser automatically places the first three into the first row and creates another row for the remaining items. This is automatic placement.

.collections {
    display: grid;
    grid-template-columns: repeat(3, 1fr);
    gap: 1rem;
}

The declared columns belong to the explicit grid. Additional tracks that Grid creates as needed belong to the implicit grid. For introductory layouts, automatic rows are often exactly what we want.

Do not over-specify: you usually do not need to declare a fixed number of rows for a collection whose number of records may change.

7. Place selected items using grid lines

Grid lines are numbered. A three-column grid has four vertical grid lines. We can tell an item which lines it should span.

Make one record span two columns

.featured {
    grid-column: 1 / 3;
}

A useful alternative expresses the intention without depending on a particular starting line:

.featured {
    grid-column: span 2;
}

DevTools checkpoint: enable the browser's Grid overlay/inspector. Identify the column lines, then compare them with the numbers used by grid-column.

8. Responsive Grid with a media query

Week 6 introduced mobile-first media queries. They work naturally with Grid. Start with one column and introduce more columns when the content has enough space.

Narrow layout first

.collections {
    display: grid;
    grid-template-columns: 1fr;
    gap: 1rem;
}

@media (min-width: 700px) {
    .collections {
        grid-template-columns: repeat(3, 1fr);
    }
}

This is explicit and easy to reason about: one layout below the content-driven breakpoint and another above it.

9. Responsive tracks with minmax() and auto-fit

Grid can also respond to available space without a media query. This is one of its most useful collection-layout patterns.

As many useful columns as fit

.collections {
    display: grid;
    grid-template-columns:
        repeat(auto-fit, minmax(220px, 1fr));
    gap: 1rem;
}
PartRole
repeat(...)Create a repeated set of tracks.
auto-fitFit as many repeated tracks as the available space allows.
minmax(220px, 1fr)Each track should not become narrower than about 220px, but may grow to share available space.

Resize slowly: watch the number of columns change. Compare this behavior with the explicit media-query version. Neither technique is universally “better”; choose the one that expresses the layout requirement clearly.

10. Named grid areas

For page-level layouts, named areas can make the intended structure unusually readable. The strings in grid-template-areas act like a small textual map of the layout.

A digital archive page

.archive-page {
    display: grid;
    grid-template-areas:
        "header  header"
        "filters results"
        "footer  footer";
    grid-template-columns: 220px 1fr;
    gap: 1rem;
}

.site-header { grid-area: header; }
.filters     { grid-area: filters; }
.results     { grid-area: results; }
.site-footer { grid-area: footer; }

Named areas are not required for every Grid. They are particularly useful when the page has meaningful regions whose arrangement changes at different widths.

11. Make named areas responsive

One semantic document, two arrangements

.archive-page {
    display: grid;
    grid-template-areas:
        "header"
        "filters"
        "results"
        "footer";
    grid-template-columns: 1fr;
    gap: 1rem;
}

@media (min-width: 800px) {
    .archive-page {
        grid-template-areas:
            "header  header"
            "filters results"
            "footer  footer";
        grid-template-columns: 220px 1fr;
    }
}
Keep meaningful HTML source order: Grid can change visual placement without changing the document's semantic or reading order. Do not use visual rearrangement as a substitute for sensible HTML structure.

12. Grid and Flexbox work together

There is no requirement to choose one layout system for the entire page. A Grid item can contain a Flexbox layout, and a flex item can itself contain a Grid.

Grid outside, Flexbox inside

.collections {
    display: grid;
    grid-template-columns:
        repeat(auto-fit, minmax(220px, 1fr));
    gap: 1rem;
}

.collection {
    display: flex;
    flex-direction: column;
}

.collection a {
    margin-top: auto;
}
QuestionLikely starting point
Do the items mainly need distribution/alignment along one row or column?Flexbox
Do rows and columns need to work together?Grid
Is it simply ordinary document content flowing from top to bottom?Normal flow — perhaps no special layout system
Does the page contain both kinds of relationships?Combine Grid and Flexbox where each is useful

13. Modern Grid: subgrid (good to know)

A normal nested grid creates its own independent tracks. With subgrid, a nested grid can instead use tracks defined by its parent. This is useful when content inside several grid items must align to the same outer tracks.

Conceptual example

.outer {
    display: grid;
    grid-template-columns: repeat(3, 1fr);
}

.nested {
    display: grid;
    grid-column: 1 / 4;
    grid-template-columns: subgrid;
}
2026 status: subgrid is a broadly available CSS Grid feature in current browsers. It is useful modern CSS, but it is not a required Week 7 technique. First become comfortable with ordinary Grid.

14. Debugging Grid

Do not debug Grid by randomly changing properties. Inspect the structure and ask specific questions.

SymptomLikely issueWhat to inspect
The intended children are not arranged.display: grid is on the wrong element.Find the common parent of the intended grid items.
Columns overflow a narrow viewport.Tracks have rigid widths or unsuitable minimums.Inspect computed track sizes and try flexible sizing.
An item spans unexpected columns.Grid line numbers or span differ from your mental model.Turn on the Grid overlay and display line numbers.
A named-area layout does not appear.Area names do not match, or the template is invalid.Compare every grid-area name with the template.
Grid styling affects only some descendants.Only direct children are grid items.Inspect the DOM hierarchy.

15. Brief CSS selector extension: pseudo-classes

A pseudo-class selects an element based on a state or structural condition rather than adding another class to the HTML. You have probably already seen :hover.

Interaction states

.collection:hover {
    background-color: #eef6fc;
}

.collection a:focus-visible {
    outline: 3px solid #005ea8;
    outline-offset: 3px;
}

:focus-visible is particularly useful for keeping keyboard focus visible. Do not rely on hover alone to communicate information or interaction.

Structural pseudo-classes

.collection:first-child {
    /* first matching child */
}

.collection:last-child {
    /* last matching child */
}

.collection:nth-child(odd) {
    /* 1st, 3rd, 5th, ... */
}

The purpose here is recognition and simple use. Pseudo-classes form a much larger selector family; consult the reference when you need a particular state or structural relationship.

16. Integrated example: a responsive archive

At this point we can combine semantic HTML from Week 3, box styling from Weeks 4–5, responsive thinking and Flexbox from Week 6, and Grid from Week 7.

Core page layout

.archive-page {
    display: grid;
    grid-template-areas:
        "filters"
        "results";
    gap: 1.5rem;
}

.result-list {
    display: grid;
    grid-template-columns:
        repeat(auto-fit, minmax(220px, 1fr));
    gap: 1rem;
}

@media (min-width: 800px) {
    .archive-page {
        grid-template-areas: "filters results";
        grid-template-columns: 220px 1fr;
    }
}

.filters { grid-area: filters; }
.results { grid-area: results; }

Prediction and modification: before editing, explain what will happen at 799px and 800px. Then change the sidebar width, the card minimum, and the gap independently. Identify which part of the layout each change controls.

17. Optional practice

  1. Start with six simple archive records in normal flow.
  2. Turn their parent into a three-column Grid.
  3. Replace repeated 1fr values with repeat().
  4. Make one featured record span two columns.
  5. Replace the fixed three-column definition with repeat(auto-fit, minmax(...)).
  6. Add a filter/sidebar region and main results region using named grid areas.
  7. Make that page-level layout one column on narrow screens.
  8. Use DevTools Grid overlay to explain where the grid lines and tracks are.
Grid Garden: the interactive CSS Grid Garden game is excellent optional reinforcement. It lets you practise Grid properties through short visual puzzles.

18. What you should know after Week 7

  • Why CSS Grid is described as a two-dimensional layout system.
  • The difference between a grid container and grid items.
  • Rows, columns, tracks, lines, cells, areas, and gaps.
  • How fr, repeat(), minmax(), and auto-fit help define tracks.
  • How automatic placement creates additional rows.
  • How to span an item across grid tracks.
  • How named areas can describe a page layout.
  • How Grid participates in responsive design.
  • Why Grid and Flexbox are complementary rather than competing technologies.
  • How to inspect and debug Grid using browser Developer Tools.
  • What common pseudo-classes such as :hover, :focus-visible, and :nth-child() represent.
