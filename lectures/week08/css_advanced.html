1. From layout to visual behavior

CSS can already respond to states such as :hover and :focus-visible (introduced last week). It can also describe movement and gradual changes without any JavaScript. Imagine a card in a digital collection: a small visual response can communicate that the record can be opened.

Starting HTML: one archive record

<a class="archive-card" href="manuscripts.html">
    <strong>Manuscripts</strong>
    <span>Explore the collection</span>
</a>

We'll keep this example and add just one concept at a time. In real work, the linked page must exist; while experimenting, use a valid destination in your own project.

2. Transforms: move, rotate, scale

The transform property changes an element's visual appearance or position without re-laying out its surrounding boxes in normal flow. The original layout space remains allocated. Some transformed elements may visually overlap their neighbors.

Three useful transform functions

.archive-card:hover {
    transform: translateY(-8px);
}

/* Other values to try in the rule above, one at a time:
   transform: rotate(5deg);
   transform: scale(1.1);
   transform: translateX(20px) rotate(3deg);
*/
translateY()
rotate()
scale()

Hover over a box or focus it with the keyboard (Tab). The change is immediate: no transition has been defined.

Prediction: if the left box moves upwards, do the other boxes move to fill the space? Inspect the layout and then check the result in the browser.

Distinguish two ideas: translateY(-8px) visually moves the element; changing margin-top may affect layout. Both can change what you see, but they work differently.

3. Transitions: change between two states

Without a transition, a style change from :hover normally appears immediately. A CSS transition tells the browser to interpolate supported property values over a specified duration.

First: instant color change

.archive-card {
    background-color: #e9f3fb;
}

.archive-card:hover {
    background-color: #cfe8fb;
}

Then: tell the browser how to transition

.archive-card {
    background-color: #e9f3fb;
    transition: background-color 250ms ease;
}

.archive-card:hover {
    background-color: #cfe8fb;
}

Put the transition on the element's normal rule, not only on :hover, so that it works when the pointer enters and leaves.

PartMeaning
background-colorThe CSS property that changes gradually.
250msDuration: 250 milliseconds (0.25 seconds).
easeTiming function: a non-linear change of speed.
Optional delayWait before starting the transition (often unnecessary).

Combine the transition with a small transform

.archive-card {
    transition:
        background-color 250ms ease,
        transform 250ms ease,
        box-shadow 250ms ease;
}

.archive-card:hover,
.archive-card:focus-visible {
    background-color: #cfe8fb;
    transform: translateY(-6px);
    box-shadow: 0 9px 20px rgb(0 0 0 / 0.18);
}
ManuscriptsExplore the archive · try hover or keyboard focus

This is a real link to the practice section. Inspect the transition in DevTools, then try changing 250ms to 1s in a copy of the example.

Easing: compare linear, ease, ease-in, ease-out, and ease-in-out. The timing function changes the progression, not the final style.

Debugging checkpoint: temporarily remove the transition declaration and test again. Restore it, then remove transform from the hover rule. Which change controls the movement, and which controls its smoothness?

4. Transition or transform?

CSS conceptWhat it doesTypical usage
transformAlters how the element is rendered.Move or slightly enlarge a card.
transitionAnimates a change between property values.Make hover/focus feedback gradual.
:hover, :focus-visibleSelect elements in a particular interaction state.Specify when different styles apply.

These features work together but are not interchangeable. A transition can animate a changing color without any transform, and a transform can apply immediately without any transition.

5. Keyframe animations: describe a sequence

Unlike a transition that interpolates a change between states, a CSS animation can run through a named sequence of keyframes. The sequence may run automatically, repeat, or be activated by a CSS state.

A simple entrance for an archive record

@keyframes reveal-record {
    from {
        opacity: 0;
        transform: translateX(-35px);
    }
    to {
        opacity: 1;
        transform: translateX(0);
    }
}

.archive-card {
    animation: reveal-record 800ms ease-out both;
}

from means 0% of the animation and to means 100%. Additional stops such as 50% are possible. Here both is an animation-fill-mode value: styles from the keyframes can apply before and after execution as appropriate.

Archive record appears →

Hover or keyboard-focus the dashed demonstration area to replay the movement. The demo uses a CSS state as the trigger, not JavaScript.

Other animation controls to recognize

.archive-card {
    animation-name: reveal-record;
    animation-duration: 800ms;
    animation-timing-function: ease-out;
    animation-delay: 200ms;
    animation-iteration-count: 1;
    animation-fill-mode: both;
}

The shorthand animation: reveal-record 800ms ease-out both combines common settings. Use animation-iteration-count: infinite only when genuinely justified; repeating movement can be distracting.

Prediction: what changes if the second keyframe uses translateX(60px) rather than translateX(0)? What happens if the duration is doubled?

6. Choosing between transitions and animations

QuestionTransitionKeyframe animation
Needs a style change, such as hover?Usually yesNot necessarily
Defines intermediate stages explicitly?NoYes: @keyframes
Can start on initial page rendering?Not by itself for ordinary initial stylesYes
Good for simple button/card feedback?Usually the simpler choiceOften unnecessary
Performance idea: animations using transform and opacity are often easier for the browser to optimize than animations that repeatedly change layout-related properties. Avoid motion that serves no useful purpose.

7. Accessible motion: respect user preferences

Some people prefer less visual movement. Operating systems can communicate this preference to the browser. CSS provides the media feature prefers-reduced-motion.

Remove nonessential movement when requested

@media (prefers-reduced-motion: reduce) {
    .archive-card {
        transition: none;
        animation: none;
    }
}

This is the same @media mechanism used for responsive layout, but it responds to a user preference rather than viewport width. Not all motion must always be removed: retain information and feedback while reducing unnecessary movement.

Inspection: in Developer Tools, find the CSS media emulation controls (browser support varies) and emulate reduced motion. Check that the example remains usable even when the transition or animation is disabled.

Accessibility rule: do not rely only on a hover animation to communicate essential information. Keyboard focus must remain visible, and the interface must make sense without animation.

8. External CSS libraries: what are we importing?

A CSS library distributes styles written by someone else. A framework usually offers a broader set of reusable conventions, utilities, and components. The browser still interprets CSS; the framework does not replace the browser's layout engine.

Bootstrap

Ready-made component styles and utilities, useful for quickly assembling conventional interfaces.

Tailwind CSS

A utility-first approach: compose many small classes directly in HTML to create a design.

Animate.css

A specialized library providing predefined CSS animations via class names.

There are also smaller libraries and alternatives, including Bulma and Hover.css. We will recognize the main approaches, not attempt to learn an additional framework in one session.

9. Bootstrap: components and utility classes

Bootstrap provides conventional styles for buttons, cards, forms, navigation, and responsive layouts. Its btn and btn-primary classes are meaningful because Bootstrap supplies the corresponding CSS rules.

Bootstrap component example

    Explore archive

The class names are not built into HTML. Remove the Bootstrap stylesheet and they no longer create Bootstrap's visual appearance. Many Bootstrap interactive components also use JavaScript; a styled button does not require the Bootstrap JavaScript bundle.

DevTools exercise: inspect a Bootstrap button in an independent demo page. Which rules come from the external stylesheet? What happens when you disable that stylesheet in the Network or Styles panel?

10. Tailwind CSS: utilities rather than predefined components

Tailwind emphasizes composing small, single-purpose classes. The classes often correspond closely to CSS concepts you already know: spacing, background colors, typography, borders, and responsive variants. This is commonly described as utility-first CSS, related to the broader idea of atomic CSS.

Tailwind 4: browser playground setup (development only)

<script src="https://cdn.jsdelivr.net/npm/@tailwindcss/browser@4"></script>

Tailwind button: styling composed in class attributes

<button class="bg-blue-600 text-white px-4 py-2 rounded">
    Explore archive
</button>

Compare the classes with their rough underlying CSS ideas: bg-blue-600 chooses a background color; text-white sets text color; px-4 and py-2 set horizontal and vertical padding; rounded sets a border radius.

Current setup matters: Tailwind 4's Play CDN is for experimenting in the browser, not the recommended production workflow. Tailwind's normal workflow generates CSS from the classes used in the project. We do not need to install a build tool for this course.

12. A small specialized library: Animate.css

Animate.css provides ready-made keyframe animations. It offers a clear demonstration of the idea that an external stylesheet can attach animation behavior to class names.

Example: load Animate.css and add its classes

<link rel="stylesheet"
      href="https://cdnjs.cloudflare.com/ajax/libs/animate.css/4.1.1/animate.min.css">

<div class="animate__animated animate__fadeIn">
    Newly added record
</div>

A predefined class is convenient, but inspect what it does. Unnecessary animation, large dependencies, and conflicts with existing styles are possible. The same small effect may be easy to write directly using @keyframes.

13. Modern CSS: the platform continues to evolve

CSS frameworks are important, but modern browsers have also gained capabilities that once often required workarounds or additional tools. These topics are for recognition and later exploration, not extra required syntax for Week 8.

One small example of reusable theme variables

:root {
    --archive-accent: #005ea8;
}

.archive-heading {
    color: var(--archive-accent);
}

.archive-link {
    border-color: var(--archive-accent);
}

This is ordinary native CSS, not a framework feature. Many modern CSS frameworks also rely on browser-native capabilities.

14. AI-assisted styling: use it, inspect it, understand it

AI coding assistants can suggest visual designs, generate CSS rules, and help explain an unfamiliar stylesheet. They are also capable of producing redundant declarations, incorrect selectors, inaccessible effects, unnecessary dependencies, and code that works only at one screen size.

Classroom experiment: give an AI tool a constrained task

Example prompt: "Improve the appearance of these digital heritage cards using vanilla CSS only. Keep the existing semantic HTML and responsive Grid layout. Add subtle hover and keyboard-focus feedback. Respect reduced-motion preferences. Explain each CSS rule and do not introduce a framework."

Evaluate the result by examining the generated code rather than relying only on a screenshot:

  1. Can you explain every CSS selector and declaration it added?
  2. Do the new declarations duplicate or conflict with existing rules?
  3. Does the result work at narrow and wide viewport sizes?
  4. Are text contrast, keyboard focus, and reduced-motion behavior appropriate?
  5. Can the same result be achieved with fewer, clearer rules?

Live debugging: compare a long generated stylesheet with a minimal handwritten version. In DevTools, disable rules one by one and determine which are actually responsible for the desired effect.

Course principle: using AI does not replace the obligation to understand, test, and explain submitted code. Do not accept invented CSS properties or API names without checking documentation.

15. A practical workflow for external styles and generated CSS

1. Inspect

Read the HTML and identify the element or class you want to style.

2. Predict

State what rule should produce the intended visible change.

3. Test

Use Developer Tools, resize the page, and try keyboard navigation.

4. Simplify

Remove unnecessary rules; keep a small comprehensible result.

If styles do not work, check whether the stylesheet loaded in the Network panel, whether the selector matches in Elements, and whether another declaration wins in the computed styles. A framework does not remove the need to understand the cascade.

16. Integrated practice: polish a digital heritage collection

Start from the responsive archive cards created in Week 7. Do not start a new large site. Improve the existing page incrementally and observe each change in the browser.

  1. Required: select a collection card and apply a small visual transform on :hover.
  2. Required: add a transition to make its color or transform change gradually.
  3. Required: ensure a keyboard user can identify the focused card or its link.
  4. Required: add a prefers-reduced-motion rule for nonessential effects.
  5. Required: use DevTools to find the rule controlling movement and the rule controlling timing.
  6. Optional: create a one-time entrance animation using @keyframes.
  7. Optional: reproduce one small component in a separate Bootstrap or Tailwind demo file, then explain how it differs from vanilla CSS.
  8. Optional: ask an AI assistant to suggest an improvement; retain only code you can justify and test.
Completion criterion: a student can explain which CSS property changes an element, what triggers that change, what controls its timing, and why the page remains usable without motion.
