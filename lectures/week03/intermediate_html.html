DE0824 Web Development · Week 3

Intermediate HTML: semantic structure and richer documents

We now move from a small collection of basic HTML elements to pages that describe meaningful document regions, structured data, user input, media, quotations, dates, figures, and embedded resources.

Course home Week 2 HTML basics Practice tasks Element reference

Week 3 goal: build a semantically meaningful HTML page without using CSS for the student's own page. By the end of this session, the browser output may still look plain, but the document should have a clear structure that both people and software can understand.

About this teaching page: like the Week 2 reference page, this document uses CSS internally to make a long teaching resource easier to read. The examples we are learning from remain HTML-focused. CSS itself begins in Week 4.

1. Start from the Week 2 vocabulary

Week 2 established the basic HTML document and the most frequently used content elements: headings, paragraphs, lists, links, images, and simple inline meaning. We will keep using those elements rather than re-teaching them.

Starting point · A simple Week 2 page

<!DOCTYPE html>
<html lang="en">
<head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>Latvian Cultural Heritage Collection</title>
</head>
<body>
    <h1>Latvian Cultural Heritage Collection</h1>

    <p>
        A small collection of digitised cultural heritage resources.
    </p>

    <h2>Collections</h2>
    <ul>
        <li>Historical newspapers</li>
        <li>Photographs</li>
        <li>Manuscripts</li>
    </ul>
</body>
</html>

Question: the page above has meaningful content, but can a browser, search engine, accessibility tool, or future programmer easily tell which part is navigation, which part is the main content, and which part is supplementary information?

2. Semantic page structure

HTML provides elements whose names describe common regions of a document. These are often called semantic elements because they communicate the role of the content, not merely its visual appearance.

<header> <nav> <main> <section> <article> <aside> <footer>
Element Typical role Possible Digital Humanities example
<header> Introductory material for a page or section. Project title, collection title, short introduction.
<nav> A major set of navigation links. Home, Collection, People, Places, About.
<main> The dominant content of the current page. The actual edition, catalogue, essay, or collection record.
<section> A thematic section, normally with a heading. Description, Metadata, Sources, Bibliography.
<article> A self-contained composition that could make sense independently. One newspaper record, manuscript record, blog entry, or research note.
<aside> Related but secondary content. Glossary, contextual note, related objects, author biography.
<footer> Closing information for a page or section. Copyright, provenance, contact information, related links.

Example 1 · Turning a flat page into a semantic document

<body>
    <header>
        <h1>Latvian Cultural Heritage Collection</h1>

        <nav>
            <a href="index.html">Home</a>
            <a href="collection.html">Collection</a>
            <a href="about.html">About</a>
        </nav>
    </header>

    <main>
        <section>
            <h2>About the collection</h2>
            <p>
                This project introduces selected digitised cultural
                heritage objects from Latvia.
            </p>
        </section>

        <section>
            <h2>Featured objects</h2>

            <article>
                <h3>Historical newspaper</h3>
                <p>A digitised newspaper from the early twentieth century.</p>
            </article>
        </section>

        <aside>
            <h2>Related resources</h2>
            <p>Links to external catalogues can appear here.</p>
        </aside>
    </main>

    <footer>
        <p>DE0824 example project</p>
    </footer>
</body>
Prediction: if you replace every semantic container above with <div>, the browser may display almost the same thing. What information about the document would be lost?

Section or article?

This distinction is not based on appearance. A useful working rule is: use <section> for a thematic part of a larger document, and <article> for content that is reasonably self-contained.

Good use of section

<section>
    <h2>Bibliography</h2>
    ...
</section>

Good use of article

<article>
    <h2>Object 1542</h2>
    ...
</article>

A semantic element is not automatically "better" merely because it has a meaningful name. Choose the element that actually describes the role of the content.

3. Identifying and grouping elements: id, class, div, and span

Before we begin CSS next week, we need to understand two global attributes and two generic container elements that appear throughout real HTML.

id attribute class attribute <div> <span>

The id attribute

An id identifies one specific element in the document. One immediate use is linking directly to a particular part of the current page.

Example 2 · Linking to an element by id

<nav>
    <a href="#bibliography">Jump to bibliography</a>
</nav>

...

<section id="bibliography">
    <h2>Bibliography</h2>
    ...
</section>

The class attribute

A class places one or more elements into a named category. Many elements may share the same class. This becomes particularly important when we start CSS selectors.

Example 3 · Several elements in the same category

<article class="collection-item">...</article>
<article class="collection-item">...</article>
<article class="collection-item">...</article>

Generic containers

<div> is a generic block-level container and <span> is a generic inline container. Use a semantic element when one describes the content; use these generic containers when no more meaningful HTML element fits.

Example 4 · Generic grouping

<div class="metadata">
    <p>Creator: Rainis</p>
    <p>Date: 1905</p>
</div>

<p>
    Original language:
    <span class="language">Latvian</span>.
</p>

Do not replace every element with <div>. Generic containers are useful, but semantic HTML gives the document more information about what its content means.

4. Figures and captions

Images in scholarly and cultural-heritage pages frequently belong together with a caption, source, identifier, or explanatory note. HTML provides a semantic structure for this.

<figure> <figcaption> <img>

Example 5 · Image with a semantic caption

<figure>
    <img
        src="../../img/rtu_logo_en-1978560996.png"
        alt="Riga Technical University logo"
    >

    <figcaption>
        Riga Technical University logo used in the DE0824 course repository.
    </figcaption>
</figure>

Remember that alt text and a visible <figcaption> are not the same thing. Alternative text communicates the image when it cannot be seen; a caption is visible document content associated with the figure.

5. Quotations, citations, dates, and abbreviations

HTML can represent more than headings and paragraphs. For scholarly text it is useful to mark quotations, titles of cited works, machine-readable dates, and abbreviations explicitly.

<blockquote> <q> <cite> <time> <abbr>

Example 6 · A block quotation and a cited work

<blockquote cite="https://example.org/source">
    <p>
        A longer quotation from a historical source can be represented
        as a block quotation.
    </p>
</blockquote>

<p>
    Source: <cite>Title of the Historical Work</cite>
</p>

Use <blockquote> for a substantial quotation presented as a block. For a short quotation inside a sentence, <q> is available. The <cite> element represents the title of a cited creative work.

Example 7 · Human-readable and machine-readable date

<p>
    Latvia proclaimed independence on
    <time datetime="1918-11-18">18 November 1918</time>.
</p>

This illustrates an important Web principle: the visible text can be written naturally for readers while an attribute supplies a standardized value for software.

Example 8 · Abbreviation with its expansion

<p>
    <abbr title="Riga Technical University">RTU</abbr>
    offers the DE0824 Web Development course.
</p>

6. Description lists for terms and metadata

Week 2 introduced ordered and unordered lists. A description list is useful when content naturally consists of names and associated values or explanations.

<dl> <dt> <dd>

Example 9 · Cultural heritage metadata

<dl>
    <dt>Creator</dt>
    <dd>Rainis</dd>

    <dt>Date</dt>
    <dd>1905</dd>

    <dt>Language</dt>
    <dd>Latvian</dd>

    <dt>Object type</dt>
    <dd>Manuscript</dd>
</dl>

Choose the structure: would this metadata be better represented by four unrelated paragraphs, an unordered list, a description list, or a data table? More than one representation may be valid, but the structure should reflect the relationships in the data.

7. Tables: representing tabular data

Tables are appropriate when information genuinely has rows and columns. They are not a page-layout mechanism.

<table> <caption> <thead> <tbody> <tr> <th> <td>

Example 10 · A small data table

<table>
    <caption>Selected historical newspapers</caption>

    <thead>
        <tr>
            <th scope="col">Title</th>
            <th scope="col">Year</th>
            <th scope="col">Language</th>
        </tr>
    </thead>

    <tbody>
        <tr>
            <td>Jaunākās Ziņas</td>
            <td>1911</td>
            <td>Latvian</td>
        </tr>

        <tr>
            <td>Baltijas Vēstnesis</td>
            <td>1868</td>
            <td>Latvian</td>
        </tr>
    </tbody>
</table>

A table row uses <tr>. Header cells use <th> and data cells use <td>. The scope="col" attribute explicitly associates a header with its column, which improves the structural meaning and accessibility of the table.

Historically, HTML tables were sometimes abused to position page content. Do not do that. Use tables for tabular data; CSS will handle layout beginning next week.

8. Forms: collecting user input

Forms introduce another important role for HTML: describing controls that accept data from the user. We are not building a server in Week 3; the goal is to understand the HTML structure. Later JavaScript can also read and react to these controls.

<form> <label> <input> <textarea> <select> <option> <button> <fieldset> <legend>

Example 11 · A simple collection search form

<form>
    <label for="search">Search the collection:</label>
    <input id="search" name="search" type="text">

    <button type="submit">Search</button>
</form>

The for="search" attribute on the label matches the id="search" on the input. This creates an explicit relationship between the text label and the control.

Example 12 · Several common form controls

<form>
    <fieldset>
        <legend>Catalogue search</legend>

        <p>
            <label for="query">Search term:</label>
            <input
                id="query"
                name="query"
                type="text"
                required
            >
        </p>

        <p>
            <label for="year">Year:</label>
            <input
                id="year"
                name="year"
                type="number"
                min="1500"
                max="2026"
            >
        </p>

        <p>
            <label for="language">Language:</label>
            <select id="language" name="language">
                <option value="lv">Latvian</option>
                <option value="en">English</option>
                <option value="de">German</option>
            </select>
        </p>

        <p>
            <label for="notes">Research notes:</label><br>
            <textarea id="notes" name="notes" rows="4"></textarea>
        </p>

        <button type="submit">Search</button>
    </fieldset>
</form>
Attribute Purpose
type Chooses the kind of input control, such as text, number, email, date, checkbox, or radio.
name Names the value when form data is submitted or processed.
value Provides or represents the control's value.
required Indicates that the user must provide a value before normal form submission.
min / max Set boundaries for compatible controls such as numbers and dates.

A placeholder is not a substitute for a <label>. Labels describe controls persistently and establish useful semantic and accessibility relationships.

9. Audio and video

HTML can embed media directly. This is relevant to oral histories, interviews, field recordings, archival film, and other Digital Humanities material.

<audio> <video> <source>

Example 13 · Audio

<audio controls>
    <source src="audio/interview.mp3" type="audio/mpeg">
    Your browser does not support embedded audio.
</audio>

Example 14 · Video

<video controls>
    <source src="video/archive-film.webm" type="video/webm">
    Your browser does not support embedded video.
</video>

The controls Boolean attribute asks the browser to provide its standard media controls. The <source> element identifies a media resource and its MIME type.

Media files can be large. In real projects we must consider bandwidth, formats, licensing, captions or transcripts, and whether a dedicated media platform is more appropriate than serving the file ourselves.

10. Embedding external content with iframe

An <iframe> embeds another browsing context—effectively another web page— inside the current page. Common examples include YouTube videos, maps, and specialized external viewers.

<iframe>

Example 15 · Generic embedded resource

<iframe
    src="https://example.org/embedded-resource"
    title="Interactive map of historical locations"
></iframe>

Use the provider's official embed code when one is supplied. Not every web page can be embedded, and third-party embeds can have privacy, security, and performance implications. A meaningful title helps identify the embedded content.

11. A few useful text-structure elements

These elements are useful but do not need an entire lecture section of their own.

<hr> <br> <pre> <code>
Element Meaning Common mistake
<hr> A thematic break between paragraph-level topics. Thinking of it only as a decorative horizontal line.
<br> A line break that is actually part of the content, such as poetry or an address. Using repeated <br> elements to create visual spacing.
<pre> Preformatted text where whitespace is significant. Using it merely because the default font looks different.
<code> A fragment of computer code. Using it as a general-purpose monospace style.

Example 16 · Code displayed as document content

<pre><code>
&lt;h1&gt;Historical Collection&lt;/h1&gt;
&lt;p&gt;A small example page.&lt;/p&gt;
</code></pre>

12. Put the pieces together

A useful Week 3 endpoint is a small cultural-heritage record containing real document structure rather than a flat sequence of headings and paragraphs.

Example 17 · Complete semantic Digital Humanities page

<!DOCTYPE html>
<html lang="en">
<head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>Cultural Heritage Object</title>
</head>
<body>
    <header>
        <h1>Digital Heritage Collection</h1>

        <nav>
            <a href="index.html">Home</a>
            <a href="#object">Object</a>
            <a href="#metadata">Metadata</a>
        </nav>
    </header>

    <main>
        <article id="object" class="collection-item">
            <header>
                <h2>Historical Manuscript</h2>
                <p>
                    Digitised on
                    <time datetime="2026-09-19">19 September 2026</time>.
                </p>
            </header>

            <figure>
                <img
                    src="img/manuscript.jpg"
                    alt="First page of the digitised manuscript"
                >
                <figcaption>
                    First page of the manuscript.
                </figcaption>
            </figure>

            <section>
                <h3>Description</h3>
                <p>
                    This example represents a digitised cultural heritage object.
                </p>
            </section>

            <section id="metadata">
                <h3>Metadata</h3>

                <dl>
                    <dt>Creator</dt>
                    <dd>Unknown</dd>

                    <dt>Date</dt>
                    <dd>Early twentieth century</dd>

                    <dt>Language</dt>
                    <dd>Latvian</dd>
                </dl>
            </section>

            <aside>
                <h3>Research note</h3>
                <p>
                    The object may contain historical spelling and abbreviations.
                </p>
            </aside>
        </article>

        <section>
            <h2>Search related objects</h2>

            <form>
                <label for="search-related">Search term:</label>
                <input
                    id="search-related"
                    name="search"
                    type="text"
                >
                <button type="submit">Search</button>
            </form>
        </section>
    </main>

    <footer>
        <p>DE0824 Web Development example</p>
    </footer>
</body>
</html>

Inspect it in Developer Tools: open the browser's Elements/Inspector panel and expand the nested elements. The HTML source has become a tree describing the page's structure. Later JavaScript will interact with this tree as the DOM.

13. Common mistakes to diagnose

Symptom or code smell Likely issue What to ask
Almost everything is wrapped in <div>. Semantic elements have not been considered. Does HTML already provide an element for this role?
A <section> contains unrelated content and has no clear theme. The grouping may not really be a section. Can I give this section a meaningful heading?
A table is used to put content side by side. HTML is being used for visual layout. Is this genuinely row-and-column data?
Clicking a form label does not focus its input. The label's for does not match the input's id. Are the two attribute values exactly identical?
An internal link does nothing. The fragment identifier does not match an element id. Does href="#name" match id="name"?
An image has a visible caption but meaningless or missing alternative text. figcaption has been confused with alt. What should someone understand if they cannot see the image?

14. Practice tasks

Start from the small page you created in Week 2. Do not rewrite everything from scratch. Improve its structure incrementally and inspect the result after each change.

  1. Wrap the introductory part of the page in a semantic <header>.
  2. Add a <nav> containing links to at least two sections of the same page using fragment identifiers.
  3. Place the dominant content inside <main>.
  4. Create at least two meaningful <section> elements with headings.
  5. Represent one self-contained cultural-heritage item using <article>.
  6. Place an image and its caption inside <figure> and <figcaption>.
  7. Add a small metadata block using <dl>, <dt>, and <dd>.
  8. Add a simple table containing genuine row-and-column data.
  9. Add one labeled form control and a button.
  10. Add a semantic <footer> at the end of the page.

Optional challenge: include a date with <time>, a quotation with <blockquote>, or an embedded external resource with <iframe>.

15. What you should be able to do after Week 3

  • Explain why semantic HTML is preferable to generic containers when a suitable semantic element exists.
  • Structure a page using header, nav, main, section, article, aside, and footer.
  • Use id for unique identifiers and internal fragment links.
  • Use class to describe a reusable category of elements.
  • Use div and span when no more meaningful semantic element fits.
  • Associate images with captions using figure and figcaption.
  • Represent metadata using description lists where appropriate.
  • Create a semantically structured data table.
  • Create basic labeled form controls.
  • Understand the basic role of native audio/video and external iframe embeds.
  • Inspect the nested HTML tree using browser Developer Tools.

16. The bridge to Week 4

At this point our page should be structurally meaningful but visually plain. That is intentional. HTML answers questions such as:

  • What is the main content?
  • What is a section?
  • What is navigation?
  • Which text is a heading?
  • Which values belong to a table?
  • Which text labels a form control?

Week 4 introduces CSS, which answers a different set of questions: colors, fonts, spacing, borders, sizing, and layout. Keeping these responsibilities separate makes both HTML and CSS easier to understand and debug.

Week 3 principle: first make the document structure correct and meaningful. Then use CSS to control how that structure is presented.
