DE0824 Web Development · Week 6

Flexbox and responsive design

Week 5 gave us the geometry of individual CSS boxes. This week we arrange groups of those boxes, distribute available space, and make layouts adapt when the viewport changes.

Course home Week 5 layout foundations Responsive design Optional practice References

Week 6 goal: use Flexbox to build one-dimensional layouts and understand the first principles of responsive web design. By the end of the session you should be able to identify flex containers and flex items, reason about the main and cross axes, align and wrap items, give items flexible sizes, and use a simple mobile-first media query.

Connection to Week 5: the box model has not disappeared. Every flex item is still a CSS box with content, padding, border, and margin. Flexbox changes how a container lays out its direct children.

1. From individual boxes to groups of boxes

Suppose a digital collection contains several records. With ordinary block layout, the articles naturally appear one below another.

Starting HTML · three collection records

<section class="collections">
    <article class="collection">Manuscripts</article>
    <article class="collection">Newspapers</article>
    <article class="collection">Photographs</article>
</section>

That is useful normal-flow behavior. But what if we want the records to share a row when enough space is available? This is a layout problem for the parent container.

The smallest Flexbox rule

.collections {
    display: flex;
}

Live-coding checkpoint: first view the articles without Flexbox. Predict what will change, add display: flex to the parent, and inspect the result. Then remove the declaration and compare again.

2. Flex container and flex items

When an element has display: flex, it becomes a flex container. Its direct children become flex items.

Container

The parent controls the overall flex layout.

.collections {
    display: flex;
}

Items

The direct children participate in that flex layout.

<section class="collections">
    <article>...</article>
    <article>...</article>
</section>

Common mistake: putting display: flex on the cards when your intention is to arrange the cards. Ask: which element is the parent of the things I want to arrange?

3. Flexbox is one-dimensional

Flexbox lays out items along one primary dimension at a time: a row or a column. This is why it is described as a one-dimensional layout system.

A
main axis →
B
C

The two essential directions are:

  • Main axis: defined by flex-direction.
  • Cross axis: perpendicular to the main axis.

Change the main axis

.collections {
    display: flex;
    flex-direction: row;    /* default */
}

/* Try this next */
.collections {
    flex-direction: column;
}

Important mental model: do not memorize “justify = horizontal” and “align = vertical.” Instead remember: justify-content works along the main axis, while align-items works along the cross axis.

5. Align items on the cross axis

align-items controls how the items align on the cross axis. Give the container some visible cross-axis space while experimenting.

Center items on the cross axis

.collections {
    display: flex;
    min-height: 250px;
    align-items: center;
}

/* Also try:
   stretch
   flex-start
   flex-end
*/

A familiar centering pattern is therefore:

.container {
    display: flex;
    justify-content: center;
    align-items: center;
}

It works because we are centering along both axes, not because Flexbox has a special “center everything” command.

6. Use gap for spacing between items

Week 5 introduced margins as space outside individual boxes. Flex and Grid containers also support gap, which directly describes spacing between layout items.

A clear container-level spacing rule

.collections {
    display: flex;
    gap: 1rem;
}
Why this is useful: gap expresses the layout intention directly. You do not need to add a right margin to every item and then remove it from the last item.

7. What happens when items no longer fit?

By default, flex items stay on one flex line. Shrink the browser or add more cards and observe what happens before changing the CSS.

Allow additional flex lines

.collections {
    display: flex;
    flex-wrap: wrap;
    gap: 1rem;
}

Responsive idea #1: Flexbox itself can already adapt to changing available space. A responsive page does not require a media query for every change.

8. Let flex items grow and shrink

Flex items can use available space instead of having one rigid width. Three underlying concepts control this behavior: flex-grow, flex-shrink, and flex-basis.

Useful card pattern

.collection {
    flex: 1 1 220px;
}
PartMeaning in this example
flex-grow: 1The item may grow when free space is available.
flex-shrink: 1The item may shrink when space is tight.
flex-basis: 220pxUse about 220px as the item's starting size on the main axis.

You will usually use the flex shorthand rather than calculate the complete Flexbox sizing algorithm by hand. The important concept is that available space is distributed among flex items.

9. An individual item can be different

Most alignment rules belong on the container, but an individual flex item can override cross-axis alignment with align-self.

One item uses different alignment

.featured {
    align-self: flex-start;
}

The order property can change visual ordering, but use it cautiously:

.featured {
    order: -1;
}
Accessibility and semantics: visual reordering does not rewrite the HTML document. Prefer meaningful source order so reading, keyboard, and visual order do not become unnecessarily inconsistent.

10. A flex item can also be a flex container

Layout roles can be nested. A collection card can be an item in the outer layout while also arranging its own children with Flexbox.

Nested Flexbox

.collections {
    display: flex;
    flex-wrap: wrap;
    gap: 1rem;
}

.collection {
    flex: 1 1 220px;

    display: flex;
    flex-direction: column;
}

This is useful for cards whose heading, description, metadata, and link need their own internal arrangement.

12. What does responsive design mean?

Responsive web design means creating pages that adapt to different available spaces and user environments rather than assuming one fixed screen size. Flexible sizing, Flexbox, Grid, responsive media, and media queries can all contribute.

The viewport declaration already present in our pages is important on mobile browsers:

<meta name="viewport" content="width=device-width, initial-scale=1.0">
Avoid “designing for devices.” There is no reliable set of phone/tablet/desktop widths. Resize the page and introduce a breakpoint where the content and layout need one.

13. Media queries: conditional CSS

A media query applies a group of CSS rules only when its condition matches. For our first responsive examples, viewport width is enough.

A first media query

@media (min-width: 700px) {
    nav {
        flex-direction: row;
    }
}

Read it literally: when the viewport is at least 700px wide, apply these rules.

You may also encounter the opposite style:

@media (max-width: 699px) {
    /* rules for this narrower range */
}

Both forms are valid. For our examples we will usually build the narrow layout first and enhance it with min-width queries.

14. Mobile-first CSS

A simple page often works naturally as one column on a narrow viewport. We can make that our default and add a wider layout only when there is room.

Narrow layout first, wider enhancement second

.site-nav {
    display: flex;
    flex-direction: column;
    gap: 0.5rem;
}

/* Add the wider arrangement when there is room. */
@media (min-width: 700px) {
    .site-nav {
        flex-direction: row;
        justify-content: space-between;
    }
}

Live test: open responsive/device mode in browser Developer Tools and drag the viewport through 700px. Watch the computed flex-direction change as the media query starts and stops matching.

15. Flexbox + media queries

Use Flexbox for the flexible relationship between items. Add a breakpoint only when the design needs a structural change.

Example · archive page

.page-layout {
    display: flex;
    flex-direction: column;
    gap: 1.5rem;
}

@media (min-width: 800px) {
    .page-layout {
        flex-direction: row;
    }

    .filters {
        flex: 0 0 220px;
    }

    .results {
        flex: 1;
    }
}

On a narrow viewport the filters and results form a readable vertical sequence. When enough width exists, the same semantic HTML becomes a sidebar-and-content layout.

17. Flexbox versus Grid

Do not treat Flexbox and Grid as competing versions of the same feature. They solve related but different layout problems.

Flexbox · Week 6

One dimension at a time. Think primarily in terms of a row or a column and the distribution/alignment of items along its axes.

Grid · Week 7

Two dimensions together. Grid gives explicit control over rows and columns and is especially useful when both dimensions matter to the layout.

Looking ahead: Week 7 will introduce CSS Grid and continue responsive layout practice. The concepts learned today—available space, gaps, alignment, breakpoints, and semantic source order—will carry forward.

18. Optional at-home practice

Start from a small semantic HTML page rather than building a large site. A collection, bibliography, archive, museum-object list, or ordinary set of cards works well.

  1. Place three or more sibling elements inside one container.
  2. Turn the parent into a flex container and identify the flex items.
  3. Try both row and column and identify the main and cross axes each time.
  4. Experiment with at least three justify-content values.
  5. Use align-items and explain which axis it affects.
  6. Replace item margins with a container gap where appropriate.
  7. Add enough items to create a space problem, then use flex-wrap: wrap.
  8. Give cards a flexible starting size such as flex: 1 1 220px.
  9. Create one mobile-first min-width media query that changes the layout when the content needs more room.
  10. Use DevTools responsive mode and inspect which CSS declarations are active on both sides of the breakpoint.

Optional challenge: make a navigation component that is a column on narrow viewports and a row on wider viewports. Do not use JavaScript.

19. What you should be able to do after Week 6

  • Explain the relationship between a flex container and its direct-child flex items.
  • Explain why Flexbox is described as one-dimensional.
  • Identify the main and cross axes for both row and column layouts.
  • Use flex-direction, justify-content, and align-items.
  • Use gap to control spacing between flex items.
  • Use flex-wrap when items should move onto additional flex lines.
  • Explain at a practical level what grow, shrink, and basis mean.
  • Use a simple flex shorthand for flexible cards.
  • Recognize when nested Flexbox is useful.
  • Explain responsive design as adaptation to available space rather than a list of device sizes.
  • Read and write a basic width-based @media rule.
  • Build a simple mobile-first layout with a min-width breakpoint.
  • Use browser Developer Tools to test Flexbox and responsive behavior.
  • State the basic distinction between one-dimensional Flexbox and two-dimensional Grid.
