JavaScript: Functions, DOM and Events

From reusable instructions to interactive web pages: define functions, select HTML elements, and respond to clicks.

Connection to Weeks 9–11: You can already use variables, expressions, if statements and loops. Now we will package instructions into functions and connect JavaScript to the HTML page. Arrays and more detailed input events follow in Week 13.

Learning goals: define and call functions; distinguish parameters, arguments, and return values; recognize local scope; explain the DOM; select an element with querySelector(); change textContent; register a click handler with addEventListener(); and debug common mistakes.

1. From instructions to interactions

Previously we ran JavaScript when a page loaded or when we typed code into the Console. A browser can also run our code later, when someone clicks a button. Functions give these instructions names; the DOM gives JavaScript access to the page.

HTML document → DOM → JavaScript selects an element → User clicks → Handler changes DOM → Visible result

2. Functions: reusable instructions

A function declaration defines a named block of instructions. Defining it does not run its body. To run it, call the function using parentheses.

Classify a historical publication

function classifyYear(year) {
    if (year < 1900) {
        return "Before 1900";
    } else if (year < 2000) {
        return "20th century";
    } else {
        return "21st century or later";
    }
}

console.log(classifyYear(1925)); // 20th century
console.log(classifyYear(1850)); // Before 1900

year in the declaration is a parameter; 1925 in the call is an argument. return sends a value back to the caller and ends that function call. This simplified classifier assumes valid positive CE years.

Zero, one, or two parameters

function announce() {
    console.log("Archive opened");
}
function greet(name) {
    return "Hello, " + name + "!";
}
function addNumbers(a, b) {
    return a + b;
}

announce();
console.log(greet("Marta"));
console.log(addNumbers(5, 10));

Returning versus printing: console.log() displays a value in the Console but does not return that value from your function. A function with no explicit return returns undefined.

Compare two behaviors

function makeGreeting(name) {
    return "Hello, " + name;
}
function printGreeting(name) {
    console.log("Hello, " + name);
}

const first = makeGreeting("Anna");
const second = printGreeting("Anna");
console.log(first);  // Hello, Anna
console.log(second); // undefined

Predict before running: How many greetings appear? What is stored in first and second? Change the argument and test in Developer Tools → Console.

3. Local variables and scope

A variable declared inside a function is local to that function. Code outside it cannot directly access that variable. Parameters are local too.

Local calculation

function describePages(pageCount) {
    const label = pageCount >= 100 ? "Long" : "Short";
    return label + " document";
}
console.log(describePages(120));
// console.log(label); // ReferenceError: label is not defined

The conditional expression condition ? a : b is a compact alternative to a simple if...else; it is not required for today's exercises. You may rewrite it using the branching statements from Week 10.

4. The DOM: HTML as objects

The browser parses HTML into the Document Object Model (DOM): a tree of nodes, including elements. JavaScript can access these objects through document. The DOM is not the HTML source file; changing it updates the current page without rewriting that file.

Start with familiar HTML

<h2 id="message">Welcome to the archive</h2>
<button id="change-button" type="button">Change message</button>

Select an element and change its text

const message = document.querySelector("#message");
message.textContent = "Archive is ready!";

#message is the same ID selector syntax you learned in CSS. querySelector() returns the first matching element, or null when nothing matches. textContent sets text, not HTML markup. Inspect the element in Developer Tools → Elements before and after the change.

Common error: a misspelled ID gives null. Trying to set null.textContent produces a TypeError. Also ensure the HTML elements exist before the script runs: use <script src="script.js" defer></script> in the document head, or place a regular script at the end of the body.

Try it: change a heading

5. Events: let the browser call your function

A click event occurs when the user activates a button. Register a function as an event listener so the browser can call it later.

A named click handler

const message = document.querySelector("#message");
const button = document.querySelector("#change-button");

function changeMessage() {
    message.textContent = "Archive is ready!";
}

button.addEventListener("click", changeMessage);

Crucial distinction: changeMessage refers to the function. changeMessage() calls it immediately and passes its return value (here undefined) instead of registering the intended handler. For today's examples, prefer named functions so you can see this distinction clearly.

Predict: What happens if the last line becomes button.addEventListener("click", changeMessage());? When does the text change? Why does clicking later no longer work?

6. Events and state: a click counter

Sometimes an event needs to remember information between clicks. Declare a counter outside the handler, then update it inside the handler. A let variable can be reassigned.

Counter logic

let clickCount = 0;
const output = document.querySelector("#count-output");
const countButton = document.querySelector("#count-button");

function countClick() {
    clickCount++;
    output.textContent = "Clicks: " + clickCount;
}

countButton.addEventListener("click", countClick);

Try it: count and reset

Clicks: 0

Modify: Make each click add two. Then display a different message after the fifth click. What changes if let clickCount = 0 is moved inside the handler?

7. Integrated example: archive record viewer

Combine a function, a conditional, a DOM selection, and a click handler. This example uses a fixed record so that detailed form handling can wait until Week 13.

Reusable classification function

function classifyYear(year) {
    if (year < 1900) {
        return "Before 1900";
    } else if (year < 2000) {
        return "20th century";
    }
    return "21st century or later";
}

function showRecord() {
    const classification = classifyYear(1925);
    document.querySelector("#record-result").textContent =
        "1925: " + classification;
}
document.querySelector("#record-button")
    .addEventListener("click", showRecord);

The highlight button demonstrates another kind of DOM change: element.classList.toggle("selected") adds or removes a CSS class. The CSS determines the appearance, while JavaScript decides when the class changes.

Change a CSS class without rewriting styles

function toggleHighlight() {
    const card = document.querySelector("#record-card");
    card.classList.toggle("selected");
}
document.querySelector("#highlight-button")
    .addEventListener("click", toggleHighlight);

9. Practice exercises

  1. Required — predict: Explain the results of classifyYear(1899), classifyYear(2000), and a function that prints a message but has no return.
  2. Required — modify: Create a heading and button. Clicking the button must change the heading's text using a named function and textContent.
  3. Required — extend: Build a counter with increment and reset buttons. Show the count on the page, not only in the Console.
  4. Required — debug: Correct a wrong selector, a handler registered with parentheses, and a script loaded before its HTML without defer.
  5. Optional challenge: Extend the archive viewer to show a different fixed publication year on a second button and toggle a highlight class for matching records.

Self-check: Can you explain the sequence HTML → DOM → selection → event → function → visible change? Can you explain why a function name without parentheses is passed to addEventListener?
